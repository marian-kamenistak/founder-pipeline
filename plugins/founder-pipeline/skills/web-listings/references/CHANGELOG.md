# Changelog — /founder-pipeline:web-listings

Method-level history only. Per-run execution detail belongs in `<property>/listings/runs.jsonl`, not here.

*v1.4 — Law 5 rewritten a second time, tightening rather than loosening it. The v1.2 version had given the agent autonomous account creation and password handling via a password-manager CLI. That was wrong: the platform's browser-automation rules prohibit the agent creating accounts or entering passwords into any field, and state explicitly that user authorization does not lift the prohibition. Law 5 now reads "the agent submits; the agent never authenticates" — anonymous forms are in scope with a per-submission confirmation, and account creation, password entry and SSO login are owner-only. `references/automation-execution.md` rewritten to match: the credential-creation section is gone, the browser-flow and hard-stop material stays, and the Wikidata and image-upload gotchas stay because they are genuinely reusable. `/founder-pipeline:web-backlinks` Phase 4.4b carries the same boundary and the reasoning behind the reversal; the two skills now agree, where previously they contradicted each other.*

*v1.3 — added `speaker` as a formal target category, sourced from a dedicated research pass, with four verified catalog rows added and four more left out rather than added unverified. Added a speaker-specific copy-tier pattern to `entity-pack.md`: speaker-bureau copy is a distinct register from mentoring or consulting copy and should not be reused across the two. `SKILL.md`'s brand-class table gained `speaker` under personal-brand. Two data-integrity lessons from the same pass, both now rules: an ad-hoc queue task that never made it into the catalog is invisible to every subsequent run, so formalise first and execute second; and a task can be mismatched at source (a target that turns out to have no profile system at all is not a listing target), which is a decision to surface, not a task to execute as written.*

*v1.2 — the entity-registration plan turned executable. Phase 4 and `method.md`'s submission mechanics rewritten with a concrete numbered sequence; new `references/automation-execution.md` for the browser mechanics. Scope model changed: registering a property as a *product* on launch-discovery platforms became an explicit per-property choice rather than something derived from `brand_class`, and visual assets moved to each site's own live favicon/og:image instead of waiting on a design task. Also established the pairing pattern — the skill holds methodology, catalog and rules; a project folder alongside it holds scripts and run state.*

*v1.1 — new "Why this skill outranks its reputation" section carrying the off-page AI-citation evidence, and `review` promoted from a marketplace-saas-only category to every brand class, with a per-class platform-fit table. Driver: an evidence sweep found every large measured AI-citation effect is off-page, the single biggest swing in the dataset being third-party review-profile presence — a 1% median citation rate without a profile vs 53.5% with 1–13 reviews [Seer, 804,491 AI responses]. Recorded with its caveats intact: correlational, the vendor's own client portfolio, the platform studied skews B2C, and 1–13 reviews is too few to be causal — so the finding is read as "a credible third-party review profile exists at all", not "get on that specific platform". Laws unchanged; this is priority weighting only. Sibling section added to `/founder-pipeline:web-backlinks`.*

*v1.0 — created. Split out of a post-launch activation checklist (which had an unstructured territory map with no dates, no submit URLs and no state) and out of `/founder-pipeline:web-backlinks` Family 3 (which owned directory tactics, but as earned-link work rather than identity listings). Owns Mode B register-once profile listings across a whole portfolio: the catalog (`config/targets.json`), the submission method (`references/method.md`), and a tracked ledger.*
